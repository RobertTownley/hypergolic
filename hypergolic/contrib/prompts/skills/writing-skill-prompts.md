A skill costs tokens only when activated, and every later call in the turn re-reads it. Shape it so an agent reads only the branch it needs
- Parent is a map: a few lines that answer the most frequent question alone (git: how to land); activation lists its sub-skills
- One sub-skill per path an agent takes. Its description says when to open it ("publish to GitHub"), not what it holds ("PR details")
- Split what different readers need; keep together what one reader always needs together
- Facts that change belong in /shared/knowledge; the skill names the file or the `apropos` words
- Point at source (`/tools/<name>/source`, /hypergolic) instead of restating an API
